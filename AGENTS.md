# AGENTS.md

This file is the operating manual for agents working in this repository. `README.md`
explains the design rationale; this file explains how the pieces are actually wired,
which commands are authoritative, and what will break if you change something carelessly.

Read this file fully before editing. If a change does not fit one of the recipes below,
find the existing module that does something similar and follow its pattern.

## At a glance

- One NixOS flake, `x86_64-linux` only.
- Hosts: `apollo` (main workstation) and `iso` (Calamares installer image).
- Built with flake-parts, import-tree, and home-manager.
- Desktop stack: niri + Noctalia, Catppuccin, zsh, starship, yazi, tmux.
- Nix implementation is Lix 2.96, selected in `modules/core/common/lix.nix`.
- `nixpkgs` is `nixos-unstable`; `nixpkgs.config.allowUnfree = true`.
- `flake.nix` is generated by flake-file. `outputs.nix` is the real entry point.

## Evaluation flow

This is the mental model you need in order to understand everything else.

```
flake.nix                              generated; outputs = import ./outputs.nix inputs
└── outputs.nix                        flake-parts.mkFlake
    ├── imports modules/.../neovim/_package.nix
    ├── imports modules/.../noctalia/_package.nix
    ├── import-tree ./modules/repository   flake-file input declarations
    └── import-tree ./modules/tree
        ├── modules/tree/hosts.nix         imports ../../hosts
        │   └── hosts/default.nix          imports hosts/*/host.nix
        └── modules/tree/module.nix        declares the `hosts` option and builds hosts
```

`modules/tree/module.nix` is the center of the architecture. It declares a
flake-parts option named `hosts` (not a NixOS option) and turns every enabled
entry into `flake.nixosConfigurations.<name>`:

```nix
modulePath = ../../modules;
rolesPath = modulePath + /core/roles;

commonTrees = [
  (modulePath + /options)
  (modulePath + /core/common)
  (modulePath + /core/profiles)
  (modulePath + /hardware)
  (modulePath + /system)
];

mkHost = host:
  inputs.nixpkgs.lib.nixosSystem {
    system = "x86_64-linux";
    specialArgs = {inherit inputs;};

    modules = lib.flatten [
      (map (tree: inputs.import-tree tree) commonTrees)
      (map (role: inputs.import-tree (rolesPath + "/${role}")) host.roles)
      host.extraModules
      host.features

      {
        networking.hostName = host.hostName;
        system.stateVersion = host.stateVersion;
      }

      (builtins.attrValues (
        lib.mapAttrs' (name: spec: lib.nameValuePair name (userModule name spec)) host.users
      ))
    ];
  };
```

Consequences:

- Every host gets `options`, `core/common`, `core/profiles`, `hardware`, and `system`.
  These trees are imported for every machine, so adding a program or option does not
  require editing a host or an import list.
- Only the role directories named in `host.roles` are imported for that host.
- `host.extraModules` and `host.features` are per-host.
- `hostName` and `stateVersion` are set inline; everything else comes from modules.
- `specialArgs = {inherit inputs;}` makes `inputs` available in every NixOS module.
- `lib.filterAttrs (_: host: host.enable)` means `hosts.<name>.enable = false`
  produces no `nixosConfiguration` at all.

`modules/repository/inputs.nix` is flake-file configuration. It declares the flake
inputs; it does not define hosts and is not imported into NixOS systems.

## Directory layout

```
flake.nix                 generated by flake-file; never edit by hand
outputs.nix               flake-parts entry point; systems, formatter, explicit _package imports
flake.lock

hosts/
  default.nix             manually imports each host's host.nix
  apollo/host.nix         host declaration for the workstation
  apollo/fs.nix           btrfs/EFI layout for apollo; pulled in via extraModules
  iso/host.nix            host declaration for the installer
  iso/live.nix            ISO-only config (Calamares, network overrides); via extraModules

modules/
  tree/
    module.nix            flake-parts `hosts` option and mkHost
    hosts.nix             bridge that imports ../../hosts
  repository/
    inputs.nix            flake-file input declarations
  options/
    module.nix            imports the other option files
    device.nix            modules.device.*   hardware capabilities
    profiles.nix          modules.profiles.* software bundles
    programs.nix          modules.system.programs.*
    system.nix            modules.system.* (loader, doas, fonts, zram, ...)
  core/
    common/               always imported for every host
    roles/                imported only for a host that lists the role
    profiles/             always imported; their config is gated by profile options
  hardware/               always imported; config gated by device/system/program options
  system/                 always imported; config gated by system/program options
  system/programs/name.nix    program implementation
  system/programs/name/       implementation plus assets/shared files
  system/programs/name/_foo.nix  shared Nix code/data; skipped by import-tree
```

### What import-tree imports

import-tree recursively imports every `.nix` file under a tree, except paths
containing a `_`-prefixed file or directory. Non-Nix files (TOML, PNG, etc.) are
ignored. This is why:

- `_settings.nix`, `_policies.nix`, and `_package.nix` are not auto-imported.
- `neovim/_settings.nix` and `browser/_policies.nix` are imported explicitly by
  the module that needs them.
- `neovim/_package.nix` and `noctalia/_package.nix` are explicitly imported by
  `outputs.nix` because they are flake-level modules, not NixOS modules.
- `noctalia/config.toml` and `noctalia/assets/` are safely beside the module.

`module.nix` has no special meaning to Nix or import-tree. It is a naming convention
for the main file of a directory. Any `.nix` file in a tree is imported.

## Host model

`hosts.<name>` is a flake-parts submodule with these fields:

| Field | Meaning |
|---|---|
| `enable` | Build this host at all. Filtered in `mkHost`. |
| `hostName` | Becomes `networking.hostName`. |
| `stateVersion` | Becomes `system.stateVersion`. Do not change casually. |
| `roles` | List of directory names under `modules/core/roles/`. Every `.nix` in each named directory is imported for this host. |
| `users` | Attrset keyed by account name. Each entry creates both a system account and a home-manager generation. |
| `features` | A `deferredModule` inserted into the system. Use it for enable flags and direct NixOS config for this host. |
| `extraModules` | A list of modules imported only by this host. Used for `fs.nix` and installer modules. |

Example (the real `apollo` host, shortened):

```nix
_: {
  hosts.apollo = {
    enable = true;
    hostName = "apollo";
    stateVersion = "26.05";

    users.ar175 = {
      description = "ar175";
      shell = "zsh";
      hashedPassword = "…";
      extraGroups = ["wheel" "video" "audio" "input" "adbusers"];
    };

    roles = ["graphical" "workstation" "laptop"];

    features = {
      modules = {
        device = {
          hasSound = true;
          hasBluetooth = true;
          cpu.type = "intel";
          gpu = {
            intel.enable = true;
            nvidia = {
              enable = true;
              prime = {
                enable = true;
                intelBusId = "PCI:0:2:0";
                nvidiaBusId = "PCI:1:0:0";
              };
            };
          };
        };

        system = {
          programs.ncalayer.enable = true;
          loader.enable = true;
          fonts.enable = true;
          automount.enable = true;
        };

        profiles = {
          workstation.enable = true;
          gaming.enable = false;
        };
      };
    };

    extraModules = [./fs.nix];
  };
}
```

`features` is a module value, so its content is regular NixOS config. The current
hosts write under `modules.*` because all custom options are rooted at `modules`.
It can also set stock NixOS options directly, and it can be written as a function
(`{lib, pkgs, ...}: { ... }`) if it needs module arguments.

### Users

`userModule` in `modules/tree/module.nix` expands each user as follows:

```nix
userModule = name: spec: {pkgs, ...}: {
  users.users.${name} = {
    isNormalUser = true;
    useDefaultShell = true;
    inherit (spec) description extraGroups hashedPassword;
    home = spec.homeDirectory;
    shell = pkgs.${spec.shell};
  };

  home-manager.users.${name} = {
    home.username = spec.username;
    home.homeDirectory = spec.homeDirectory;
  };
};
```

Defaults: `username = name`, `homeDirectory = "/home/${name}"`, `description = ""`,
`shell = "bash"`, `extraGroups = []`, `hashedPassword = null`. `shell` is a package
attribute name, so `"zsh"` becomes `pkgs.zsh`.

Home-manager settings for the account come from shared modules, not from a per-user
directory. Adding a user needs no home-manager file. Some modules still hardcode
`users.users.ar175`; see “Hardcoded assumptions” below.

### The three axes

1. `modules.device.*` — hardware capability: sound, Bluetooth, CPU vendor, GPUs.
   Implementations are in `modules/hardware/`.
2. `roles` — what the machine *is*. A role directory is imported wholesale for the
   host. Role code is unconditional; a graphical machine simply gets a session.
3. `modules.profiles.*` and `modules.system.programs.*` — software. Profiles are
   always imported but gated by their enable option, and they turn programs on with
   `lib.mkDefault`. A host can therefore disable one program while keeping the
   profile.

Profile and role modules use `lib.mkDefault`, so a host's normal-priority assignment
wins. For example, a host can set `modules.system.programs.browser.enable = false`
while keeping the `workstation` profile enabled, without `mkForce`.

`modules/hardware/` is organizational, not strictly device-gated: `adb.nix` and
`virtualisation.nix` live there but are gated by program options
(`modules.system.programs.adb` and `modules.system.programs.virtualisation`).

## Module implementation conventions

A normal program module looks like this:

```nix
{
  lib,
  config,
  ...
}: let
  cfg = config.modules.system.programs.gaming;
in {
  config = lib.mkIf cfg.enable {
    programs.steam.enable = true;
  };
}
```

Rules that follow from the module system:

- **Imports must be a concrete list.** The module system runs `length`/`imap1`
  over `imports`, so `imports = lib.mkIf ...` is a type error. Gate `config`, as
  above, never `imports`.
- **A plain attrset module has no arguments.** To use `pkgs`, `lib`, `config`, or
  `inputs`, write the module as a function: `{pkgs, ...}: { ... }`.
- **Feature options live in `modules/options/`.** Do not declare feature options in
  the implementation file. This keeps the option surface in one place and makes
  `rg "programs.foo"` find both the declaration and every consumer.
- **Every common module is always imported.** The `lib.mkIf cfg.enable` is what
  makes it a toggle.

### Home-manager features

A feature that configures a home-manager program declares its switch in the NixOS
module and injects a home-manager module into every account:

```nix
{
  lib,
  config,
  ...
}: let
  cfg = config.modules.system.programs.direnv;

  home = {
    programs.direnv.enable = true;
    programs.direnv.nix-direnv.enable = true;
  };
in {
  config = lib.mkIf cfg.enable {
    home-manager.sharedModules = [home];
  };
}
```

`home` may be a function taking `{config, osConfig, pkgs, ...}` when it needs
arguments. `osConfig` is the NixOS side, so a feature and its switch are not
decided in two places. `core/common/home-manager.nix` sets
`home.stateVersion = osConfig.system.stateVersion` for every user, plus
`useGlobalPkgs`, `useUserPackages`, and `extraSpecialArgs = {inherit inputs;}`.

### Overlays and flake packages

Two different mechanisms exist:

- Wrapped applications from `modules/core/common/packages.nix` are defined in
  `nixpkgs.overlays`, so they are reachable as `pkgs.myTerminal`, `pkgs.myYazi`,
  and `pkgs.myTmux` from any module.
- `modules/system/programs/noctalia/_package.nix` defines
  `flake.overlays.default` for `myNoctalia`. The Noctalia module applies
  `inputs.self.overlays.default` when enabled, which is why `pkgs.myNoctalia`
  resolves in `niri.nix`.
- `neovim/_package.nix` and `noctalia/_package.nix` also expose
  `perSystem.packages.*` and `perSystem.apps.*` for `nix build`/`nix run`.

A `_package.nix` is not imported automatically. Add it to `outputs.nix` explicitly
if you create another one.

## Recipes

### Add a host

1. Create `hosts/<name>/host.nix` with `hosts.<name> = { ... };`.
2. Add `./hosts/<name>/host.nix` (or the directory file you use) to
   `hosts/default.nix`. Registration is manual.
3. Set `enable = true`, `hostName`, `stateVersion`, `users`, and `roles`.
4. Add per-host `features` and, only if needed, `extraModules` (filesystem layout,
   kernel module, installer module).
5. Verify:
   `nix build .#nixosConfigurations.<name>.config.system.build.toplevel --dry-run`

### Add a program

1. Add `foo.enable = lib.mkEnableOption "foo";` to
   `modules/options/programs.nix`.
2. Create `modules/system/programs/foo.nix` with the `cfg`/`mkIf` pattern above.
   It is auto-imported by the `system` tree; do not add an import anywhere.
3. Enable it in a profile (with `mkDefault`) or in a host's `features`.
4. If it configures home-manager, use `home-manager.sharedModules` under `mkIf`.
5. If it needs assets or shared data, create
   `modules/system/programs/foo/` with `module.nix` and `_data.nix`/assets.
   Non-Nix assets beside the module are fine.

### Add a profile

1. Declare `modules.profiles.<name>.enable` in `modules/options/profiles.nix`.
2. Create `modules/core/profiles/<name>/module.nix` that gates on the option and
   enables programs with `lib.mkDefault`.
3. Enable the profile in a host's `features.modules.profiles.<name>.enable`.

### Add a role

1. Create `modules/core/roles/<name>/` with at least one `.nix` file.
   `module.nix` is the conventional main file.
2. Set role defaults with `lib.mkDefault`; role files are imported unconditionally
   for hosts that list the role.
3. Add `"<name>"` to a host's `roles` list. There is no other registration.

### Add a flake input

1. Edit `modules/repository/inputs.nix`.
2. Run `nix run .#write-flake` to regenerate `flake.nix`.
3. Update the lock if needed with `nix flake update <name>` (or `nix flake update`).
4. Never edit `flake.nix` directly; it will be overwritten.

### Add a flake-level package or app

1. Create `modules/system/programs/<thing>/_package.nix` (or another `_`-prefixed
   file) so import-tree does not import it into every NixOS system.
2. Add it to the `imports` list in `outputs.nix`.
3. Use `perSystem` for `packages.<name>` / `apps.<name>`, and/or
   `flake.overlays.default` for a `pkgs.<name>` overlay.
4. If it is an overlay, apply it in the consuming module (`nixpkgs.overlays = [...]`).

### Change a host's filesystem or boot setup

Put it in a per-host file (for example `hosts/apollo/fs.nix`) and add it to that
host's `extraModules`. Do not add another host's disk UUIDs or initrd modules to a
common module.

## Commands

Run these from the repository root unless noted.

| Goal | Command |
|---|---|
| Evaluate/check the flake | `nix flake check --show-trace --fallback --no-build` |
| Quick evaluation of apollo | `nix build .#nixosConfigurations.apollo.config.system.build.toplevel --dry-run` |
| Build apollo | `nix build .#nixosConfigurations.apollo.config.system.build.toplevel` |
| Build the ISO | `nix build .#nixosConfigurations.iso.config.system.build.isoImage` |
| Prove a change is inert | `nix eval .#nixosConfigurations.apollo.config.system.build.toplevel.drvPath` |
| Apply on apollo | `nh os switch` (run from `~/nixos-config`) |
| Format | `nix fmt` (alejandra) |
| Full CI formatting parity | `nix run nixpkgs#deadnix -- --edit .` then `nix run nixpkgs#statix -- fix .` then `nix run nixpkgs#alejandra .` |
| Regenerate `flake.nix` | `nix run .#write-flake` |
| Build the standalone Neovim | `nix build .#myNeovim` |
| Build the standalone Noctalia | `nix build .#myNoctalia` |

Notes:

- There is no test suite. Evaluation, builds, and `drvPath` comparison are the
  verification tools. An identical `drvPath` means the system definition did not
  change.
- `nh` is configured with `flake = "$HOME/nixos-config"` and auto-detects
  elevation; on `apollo` that resolves to `doas` because
  `modules/system/doas.nix` disables sudo.
- `nix fmt` only runs alejandra. CI also runs deadnix and statix, so run all three
  before handing off code.
- `nix flake check --no-build` still evaluates both hosts; it is the fastest
  broad sanity check.

## CI

- `.github/workflows/check.yml` — on PRs to `main` touching `modules/**`,
  `flake.nix`, `flake.lock`, or `.github/**`, on pushes to `main`, and manually.
  Runs `nix flake check --show-trace --fallback --no-build` and a dry build of
  apollo.
- `.github/workflows/format.yml` — on pushes to `main` touching `**/*.nix`, and
  manually. Runs deadnix, statix, and alejandra, then auto-commits changes as
  `chore(nix): formatting` with the GitHub Actions bot. Format locally to avoid
  surprise commits.
- `.github/workflows/build.yml` — manual. Builds the `apollo` and `iso` toplevel
  derivations and pushes to the `ar175-lol-nix` Cachix cache.
- `.github/workflows/build-iso.yml` — manual. Builds `isoImage`, splits it into
  1900 MiB parts, uploads artifacts, and optionally creates a release when a tag
  is supplied.

## Hard rules and gotchas

- **Never edit `flake.nix`.** It is generated from
  `modules/repository/inputs.nix`. Edit that file and run
  `nix run .#write-flake`.
- **Never gate `imports`.** Use `config = lib.mkIf ...`. `imports` must be a
  concrete list.
- **Respect the underscore convention.** import-tree skips `_`-prefixed files and
  directories. If you create `_package.nix` or `_data.nix`, import it explicitly
  where needed; if you want auto-import, do not prefix it.
- **Do not change `stateVersion`** unless you are intentionally performing a
  release upgrade and understand the consequences. Both hosts are `26.05`.
- **Profiles are defaults.** They use `mkDefault`; a host feature setting the same
  option at normal priority overrides them. Do not use `mkForce` to win an argument
  with a default.
- **Roles are unconditional.** A role directory is imported whole for a host that
  lists it. Do not expect a role to be a toggle; use `features` or a program option
  for behavior that must be conditional.
- **NixOS feature options are declared only in `modules/options/`.** The
  flake-parts `hosts` option is the exception, declared in
  `modules/tree/module.nix`. Implementations read `config.modules.*`.
- **Plain attrset modules get no arguments.** Use a function for `lib`, `pkgs`,
  `config`, or `inputs`.
- **Host registration is manual.** A new `hosts/<name>/host.nix` does nothing until
  it is imported by `hosts/default.nix`.
- **`features` is a module, not a nested option.** Config under
  `features.modules.*` is the same as config under `modules.*` in any other NixOS
  module. It can also set stock NixOS options directly.
- **`hosts` is a flake-parts option.** It is declared in `modules/tree/module.nix`,
  not in `modules/options/`.
- **`import-tree` imports `.nix` files only.** TOML/PNG assets are ignored; this is
  why they can sit next to `module.nix`.
- **Do not commit plaintext secrets.** `hosts/apollo/host.nix` contains a hashed
  password; do not add tokens or passwords in plaintext. `git.nix` contains the
  user's identity and signing key path.
- **CI auto-commits formatting.** Expect `format.yml` to rewrite Nix files on
  `main`; run the formatters yourself instead of relying on it.
- **`debug = true` in `outputs.nix` is intentional.** It exposes flake-parts
  `debug.options`, which the Neovim nixd setup uses for completions. Do not remove
  it casually.

- `modules/system/programs/browser/_policies.nix` — `DownloadDirectory` is

- `modules/system/programs/noctalia/config.toml` — avatar path is

- `modules/system/programs/neovim/_settings.nix` — nixd uses
  `/home/ar175/nixos-config` and the `apollo` host for option evaluation.

- `hosts/apollo/host.nix` — account name, groups, and hashed password.

## Noctalia configuration

`modules/system/programs/noctalia/config.toml` is the Noctalia shell config used to
build `pkgs.myNoctalia`. `_package.nix` replaces the `@ASSETS@` placeholder with
the path to `modules/system/programs/noctalia/assets/`, writes the result to
`$out/noctalia-config/noctalia/config.toml`, and sets `NOCTALIA_CONFIG_HOME`.

The `noctalia-sync` shell command (installed by
`modules/core/roles/graphical/shell.nix`) works in the opposite direction: it reads
`~/.local/state/noctalia/settings.toml`, rewrites asset paths to `@ASSETS@`, writes
the repo's `config.toml`, stages it, and runs `nh os switch`. Editing
`config.toml` by hand is fine, but the next `noctalia-sync` run can overwrite it.
The zsh aliases `sync` and `update` call this workflow.

## System behavior worth knowing

- Boot: xanmod latest kernel, Plymouth, quiet boot; Limine is enabled on `apollo`
  through `modules/system/loader.nix`.
- Networking: iwd with IPv6 disabled, NetworkManager off, dhcpcd off by default,
  dnscrypt-proxy on `127.0.0.1`, systemd-resolved and resolvconf disabled, nftables
  firewall on.
- Privilege: `modules/system/doas.nix` disables sudo and enables passwordless doas
  for `wheel`; the `workstation` role turns this on.
- Audio: PipeWire with ALSA, JACK, Pulse, and WirePlumber when
  `modules.device.hasSound` is true.
- GPU: NVIDIA proprietary driver with modesetting/fine-grained power management and
  optional PRIME offload; Intel i915 GuC and VA-API packages when Intel GPU is on.
- Laptop: zram swap and undervolt/thermald/power-profiles-daemon via the `laptop`
  role.
- ISO: `hosts/iso/live.nix` wraps Calamares with a Wayland/pkexec launcher, forces
  xanmod, switches to dhcpcd, disables NetworkManager/wireless, enables broad
  polkit rules, and adds installer/debootstrap tooling. Do not “clean up” this file
  without testing the ISO build and boot path.
- `modules/core/common/debloat.nix` deliberately masks or disables ModemManager,
  nscd, core dumps, timesyncd, speechd, and some systemd sockets/timers. That is
  intentional; do not re-enable them as “fixes” unless the task asks for it.
